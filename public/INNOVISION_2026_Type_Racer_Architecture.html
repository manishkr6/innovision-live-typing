1. Project Structure & Key Files

The codebase is constructed with React 19, Vite, Tailwind CSS, and the Firebase Web SDK. Below is the purpose of every core module:

File Path Primary Role & Responsibilities
src/context/AuthContext.tsx Manages participant registration sessions, localStorage caching, organizer PIN authentication, and remote roster wipe listener.
src/context/CompetitionContext.tsx Central state engine: orchestrates round creation, synchronized countdown starts, score submissions, retry grants, and real-time Firestore listeners.
src/hooks/useTypingEngine.ts High-precision millisecond typing engine: calculates dynamic WPM, Raw WPM, Accuracy, Punctuation, monitors tab switches/blurs, and detects speed bursts.
src/pages/RegisterPage.tsx Participant badge registration form: collects name, roll number, department, year, phone; validates fields; and issues competitor badge.
src/pages/ArenaPage.tsx Live competition race arena: provides the synchronized waiting lobby, connects to the 10s countdown visualizer, and presents the final ResultCard.
src/pages/AdminPage.tsx Organizer command center: live digital clock HUD, round activation, participant directory with WPM, accuracy, punctuation, retries, and database wipe.
src/utils/scoring.ts Core math engine implementing standard Net WPM, Raw WPM, Accuracy %, and strict punctuation verification algorithms.
src/lib/firebase.ts Initializes Firebase App, Auth instance, and Firestore database with long-polling failover.

2. Firebase Database Architecture

The application interacts with 4 collections and 1 configuration document in Cloud Firestore:

Collection / Document Schema & Key Fields Function
config/competition status, activeRoundId, resultsPublished, announcement, lastRosterResetAt Global competition state governing registration, live countdown, and result visibility.
participants/{id} id, name, rollNo, email, department, year, phone, canRetry, disqualified Stores competitor identity badges (no Google account login needed for students).
rounds/{id} name, passageTitle, passageText, difficulty, duration, status, startAt Championship round details and exact millisecond start time for synchronized countdowns.
attempts/{id} participantId, roundId, wpm, rawWpm, accuracy, punctuationAccuracy, errors, keystrokes Stores completed race results, keystroke telemetry, and anti-cheat audit flags.
admins/{uid} email, name, role (superadmin) Faculty coordinator and organizer admin authorization.

6. Anti-Cheat & Tournament Reliability

  • Tab Switch & Blur Monitor: Event listeners track when a student switches tabs or minimizes the window. 3+ blurs automatically flag the submission for organizer review.
  • Keystroke Cadence Analysis: Inter-keystroke intervals < 25ms are detected as script injection or copy-paste bots and flagged.
  • Centralized Epoch Timing: Clocks are synchronized via cloud epoch timestamps, preventing local computer time alterations from tampering with duration.
  • High-Concurrency Protection: Uses deterministic composite document keys (att_${roundId}_${participantId}), Map-based snapshot deduplication, and an 8-second in-flight sync grace buffer to eliminate race conditions when 10+ students finish simultaneously.
